# ReviewPilot Development Audit

**Audit date:** 2026-11-25
**Scope:** Tracked repository source, tests, application manifests and lockfiles, container and deployment configuration, CI workflow, environment examples, and README.

## Executive summary

ReviewPilot has a functioning React dashboard and FastAPI backend for fetching pull requests, asking Gemini to analyze diffs, validating finding locations, proposing single-file fixes, and optionally publishing reviews or commits through GitHub. Backend tests, the web production build, and the Express scaffold typecheck passed during this audit.

The most important release blocker is that the GitHub-backed API has no caller authentication or authorization. The review-publication and fix-publication endpoints use the server's GitHub token and accept caller-controlled publication data; the `approved` request field is not an identity or authorization check. Do not expose this service publicly with a write-capable token until API authorization, repository allowlisting, and rate/cost controls are implemented.

There is also a material mismatch between the webhook implementation and the documentation: the webhook processing path publishes GitHub review comments when findings exist, despite the README and webhook response describing publishing as disabled. Production readiness is further limited by process-local background work, optional in-memory idempotency, absent Redis configuration in the Render Blueprint, and Docker-based validation that is not available on the documented native Render service.

## Verification performed

- `cd apps/agents && python3 -m pytest -q` — **53 passed**. Two dependency deprecation warnings were emitted (`google-genai` typing compatibility and Starlette's `httpx` test-client integration).
- `cd apps/web && npm run build` — **passed**.
- `cd apps/api && npm run typecheck` — **passed**.
- The backend suite is the only configured test suite. No frontend test or lint scripts are defined in `apps/web/package.json`, and no test script is defined in `apps/api/package.json`.

## Recommended remediation order

1. **Before public deployment:** Add authentication, repository-scoped authorization, rate limits, and write-operation audit logging. Replace the client-controlled `approved` flag with a verifiable approval mechanism and restrict GitHub token permissions.
2. **Resolve webhook behavior:** Explicitly choose whether webhook-triggered comments are allowed. Make implementation, response fields, tests, and README agree; add a durable queue and production idempotency store.
3. **Make deployment reproducible:** Build the agent image from the lockfile, configure deployed `WEB_ORIGIN`, and provide Redis/worker services where required.
4. **Close user-visible and test gaps:** Show original code for fix review, implement or remove inactive navigation, and add web/API tests plus CI checks for the frontend build and Express typecheck.
5. **Reduce maintenance drift:** Remove redundant dependencies and unused scaffold/helpers only after behavior is documented and test coverage is in place.
